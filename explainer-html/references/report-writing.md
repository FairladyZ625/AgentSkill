# 汇报类文档写法（给领导、业务方、跨团队会议）

适用：周进展、阶段汇报、方案评审材料、会议材料，以及随文档发出的微信/IM 话术。这类文档读者是决策者，不看过程，只看局面、结果和要他做什么。来源：2026-10-25 得力两份汇报（《当周工作进展以及下周工作推进计划》《统一研发流程方案》）多轮返工后的定稿，业主认可。

写完跑 `validate-explainer.mjs <file> --report`，禁用表达会被拦下。

## 1. 结构：先讲大局，再讲落地

读者只看第一屏也要拿到主线，越往后越细。

| 位置 | 写什么 | 要点 |
|---|---|---|
| 导语（一句到两句） | 本期最硬的结果 + 数字 + 下一步时间点 | 例：「打印助手已在 Lab 跑通真实对话，打印设置评测通过率 88%。下周三全团队对齐统一研发流程；11 月打印助手接入真实服务，新同学按流程入职。」 |
| 第 01 节 | 目标总图（SVG）：目标 → 几条并行的线 → 时间轴 | 用对方的业务目标开头（如 11 月上线），不用自己的工程任务开头 |
| 机会 / 背景 | 在对方公司看到的机会，业务相关的排前面 | 直接列卡片，不写引言 |
| 本周进展 | KPI、真实截图、证据 | 放在大局之后，用作落地能力的证明 |
| 重点能力 | 独立成章，不挂在子节下 | 见第 2 节 |
| 节奏 | 月度/季度里程碑 | 与第 01 节时间轴一致 |
| 下周 | 按天的计划 | |
| 需要的支持 | 具体到人、事、时间 | 放最后，单独一节 |

**两份文档分工**：周报给决策者看全局，可以短；方案是会议材料，可以写细，开头加一节「背景：场景与人员」，交代为什么现在需要它。

**深度进抽屉**：拓扑、接口清单、全量截图、评测明细放 `<details>`，正文只留结论和一张主图。

## 2. 讲一个能力或工具：问题 → 目标 → 结果

不要上来介绍「它有哪些页面、哪些功能」。三张卡片：

- **遇到的问题**：具体场景里卡住的事（如「环境、账号、评测、版本散在不同地方，新同学搭环境要几天」）。
- **要达到的目标**：一句可检验的目标（如「一个入口看清环境、身份、评测与版本」）。
- **做到的结果**：已上线的东西 + 数字。

然后一张主截图，再一张「问题 → 页面 → 状态」对照表。其余截图进抽屉。

## 3. 截图与图

- 截信息量高的页面（发布清单、智能体详情这类），不截只有几个容器状态的页面。
- 截图标注来源，如「控制台预览」。
- 截图前扫描页面文本：不得出现 `sk-`、令牌、本机绝对路径、演示密码。
- 截图里的数字必须和正文口径一致。平台评测 64%、正文写本地 88% 这种冲突，换图或不放。
- 结构关系优先 SVG，遵守 [svg-diagram-rules](svg-diagram-rules.md)。

## 4. 口径

- 多地团队写成一个团队，按职责分工，不按城市分「我们 / 他们」。
- 只写对方会议原话与已知事实能支撑的判断，不替集团写战略，不碰越位话题（如别部门的备案进度）。
- 正面叙事：写做到了什么、下一步做什么。不写防御性解释。
- 超前完成的下周事项，正文仍写在计划里，完成截图放抽屉并标注「控制台预览」，节奏由业主掌握。

## 5. 禁用表达（AI 味）

| 类别 | 例子 | 改法 |
|---|---|---|
| 元叙事 | 「先给出…再用…作为证据」「下面我们来看」「本节介绍」「一页能看完全局」 | 删，直接写内容 |
| 解释打法 / 动机 | 「我们的打法是」「之所以这样做」「为什么要…」「我的判断是」 | 删主语和引子，直接写事实与计划 |
| 总结收尾句 | 「这意味着…」「一句话：…」「总之」「归根结底」 | 删；结论放段首 |
| 定性 | 「关键的一步」「意义重大」「真正的瓶颈」「本质上」「核心在于」 | 换成事实或数字 |
| 句式套路 | 「不是 A，而是 B」、三连排比、比喻 | 直接说 B；排比拆成表格或列表 |
| 防御性 | 「需要说明的是」「并非…」「这不是…只是…」 | 删，或改成正面陈述 |
| 空泛形容 | 「全面」「深度」「赋能」「闭环」「抓手」 | 换成具体动作和对象 |

自检方法：每段第一句是不是结论；删掉某句后信息是否丢失，不丢就删。

## 6. 标题与语域（会议、评审、对外材料）

会议材料用规范书面语。标题是**名词短语**（「新场景产品输入规范」「九步流程与产品职责」）或**陈述结论**（「打印机设置助手 17 轮评测通过率由 60% 升至 96%」）。

| 禁止 | 例子 | 改法 |
|---|---|---|
| 设问 / 疑问式标题 | 「测评怎么做」「现在做到哪」「产品经理站在哪」「交付物长什么样」 | 「评测机制」「当前进展」「产品职责」「交付物样例」 |
| 口语化 | 「交齐」「跑通」「搞定」「干啥」「到底」 | 「交付」「打通」「完成」或直接写对象 |
| 凑数式标题 | 「交齐 8 样东西」「要配合的五件事」 | 「产品输入清单（8 项）」「产品协作事项」 |
| 英文眉标 / 装饰标签 | 「SECTION 01 · NINE-STEP PIPELINE」「TECHNICAL EXPLAINER」 | 删；需要编号就用「一、」「1.」 |
| 第二人称导语 | 「你可以理解为」「我们来看」 | 删 |

数量放进括号或表格，不放进标题主干。小节标题、表头、`summary`、徽章标题同样适用；`--report` 校验会逐条检查。

本节与第 5 节是所有 explainer HTML 的基本文风原则，校验脚本默认执行，不依赖 `--report`。

## 7. 随文档发的微信 / IM 话术

结构固定四段，总长控制在手机一屏半内：

1. 一句交代：做了什么（「周末把来得力两周的情况整理成了两份文档」）。
2. 一段核心事实：目标 + 三条线 + 最硬的数字 + 底座优势（环境自给、过程可追溯），全部是事实。
3. 每份文档一句：写**内容是什么**，不写怎么读（禁「第一页是判断和打法」）。
4. 一句下一步：谁、从哪天、做什么；需要拍板的单独找。

同样适用第 5、6 节，尤其不写「我的判断是」「基于这个判断」。先发话术，再紧跟着发 PDF。

定稿示例：

> 张总，周末把来得力两周的情况整理成了两份文档。
>
> 11 月的目标是新 APP 带着打印助手上线，我们按产品、平台对接、研发体系三条线推进。打印助手已经在我们自建的 Lab 环境里跑通真实对话，打印设置评测通过率 88%；用户、IoT、AI、智能体四个模块的内网服务由 Mock 承担，开发不受内网限制；每个需求从立项、评审到合入都记录在 Harness 上，可以追溯。
>
> 1.《当周工作进展以及下周工作推进计划》：三条线的目标与节奏、来得力看到的六个机会、本周进展、Lab 环境，以及下周安排和需要您支持的事项。
>
> 2.《统一研发流程方案》：周三全团队对齐用的会议材料，内容较细，包括九步研发流程、系统架构、账号与版本管理、评测和设备接入设计。11 月新同学入职按这套流程上手，打印之后的场景按同样的方法复制。
>
> 周一开始我和同事们一起把流程和环境落到各自的工作里，需要您拍板的事项我单独找您。

## 7. 方案选型与汇报材料（多模式版式与高密度自解释）

针对管理层汇报、选型方案与决策材料（2026-10-27/28 泽宇裁定）：

1. **高密度「核心、优劣、原因」结构**：
   - 严禁同一组参数在“一览表 → 单方案分节 → 横向对比总表”重复三遍导致报告膨胀到十几页。
   - 每个方案按 **核心构成与成本、优势、劣势与风险、根本原因** 一步到位高密度呈现。
   - 严禁出现「材料属性」「汇报结语」「阅读说明」及表格前后的解释性废话段落。重写冗长报告时：**先砍掉所有冗余标签和说明文字；若清晰度下降，再去优化布局、合并表格、强化表头和视觉层级**。
2. **决策边界两态**：
   - **未定调前**：只阐述各方案核心、优劣、原因，不做决策引导。
   - **领导已定调后**：在方案对比后增设**推进路径与风险兜底节**，明确写出：（a）**推荐方案 + 需协同解决的前置问题（如数字化远程控制） + 明确工作风险（如差旅网络受限）**；（b）**必选兜底方案**（推荐方案受阻时的保底选择）；（c）**岗位梯队分层配置**（如高负载本地编译 FDE 配 Pro vs 云端为主的 PM 配 Air，有层级才有说服力）。
3. **多版式模式支持（非强制单一手机原生，按场景灵活选）**：
   - **手机竖屏模式 (`phone`, 390×844pt, 9:19.5)**：领导在微信/手机端快速审阅，一页对齐一屏，高信息密度推荐 6–8 屏，无横向拖动；
   - **A4 纵向模式 (`a4-portrait`, 595×842pt)**：正式公文呈报、纸质打印归档、平板/桌面阅读；
   - **A4 横向模式 (`a4-landscape`, 842×595pt)**：宽幅甘特图、复杂多列对比大表、架构全景；
   - **16:9 幻灯片模式 (`slide`, 960×540pt)**：会议室大屏演示、投屏汇报。

## 8. 交付与导出

- 汇报文档落到业主的 Brain 对应汇报目录（一期一个子文件夹，含 INDEX.md、截图素材/），不散放。
- **使用 Skill 沉淀的导出脚本一键出 PDF**：
  ```bash
  node ~/.claude/skills/explainer-html/scripts/export-pdf.mjs <输入.html> [输出.pdf] --mode <phone|a4-portrait|a4-landscape|slide|auto> [--preview]
  ```
  脚本会自动调用 Chrome Headless 渲染、检查 `pdfinfo` 页面尺寸与页数，并支持 `--preview` 自动生成 PNG 缩略图以供目测。
- 文档和话术由业主本人发送，Agent 不代发。
